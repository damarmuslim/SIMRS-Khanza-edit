## Bug Ditemukan & Diperbaiki (sesi lanjutan)

- **Logika skor EWS Nadi salah** ([PacsScoring.java](src/rekammedis/PacsScoring.java)): sebelumnya `skorNadi()` mengembalikan skor 0 untuk nadi ≤101, skor 1 HANYA untuk nadi ==102 persis, dan `null` (tak terdefinisi + munculkan peringatan) untuk nadi ≥103 — perilaku ini sebelumnya diklaim "sudah dikonfirmasi user" di komentar kode, ternyata salah. User mengoreksi: seharusnya skor 0 = ≤101, skor 1 = ≥102 (tanpa batas atas, tidak ada kasus tak terdefinisi). Diperbaiki:
    - `PacsScoring.skorNadi()`: return type diubah dari `Integer` (bisa null) ke `int` biasa, logika jadi `nadi<=101 ? 0 : 1`.
    - `RMTriaseIGD.hitungSkorOtomatisPacs()`: blok Nadi disederhanakan mengikuti pola parameter lain (TD/Respirasi/dst) — dialog peringatan "Nadi di luar kategori formulir" dan penanganan null dihapus (sudah tidak relevan).
    - Komentar-komentar yang menjelaskan aturan lama (di `PacsScoring.java`, `buatComboSkor()`, `hitungSkorOtomatisPacs()`) diperbarui/dibersihkan.
    - `PacsScoringTest.java`: 2 test lama yang mengharapkan `null` untuk nadi ≥103 diganti jadi mengharapkan skor 1; import `assertNull` yang jadi tidak terpakai dihapus.
    - Item combo "?" (dan pengecekan terkait di `hitungTotalSkorPacs()`) **sengaja dibiarkan** sebagai jaring pengaman generik meski sekarang tidak ada aturan skor PACS manapun yang menghasilkannya — bukan bug, cuma sudah tidak pernah terpicu.
    - Test: 61/61 lolos (`ant test`). Build `ant jar` sukses.

- **Cetak PACS error `Unknown column name catatan_khusus in result set`**: root cause di `cetakPacs()` ([RMTriaseIGD.java](src/rekammedis/RMTriaseIGD.java)) — query cetak dibangun manual di Java (variabel `qry`), BUKAN dari `<queryString>` di JRXML (`Valid.MyReportqry` mengeksekusi `qry` ini sendiri lewat `JRResultSetDataSource`, mengabaikan queryString bawaan file .jasper). Saat field "Catatan Khusus" ditambahkan ke JRXML (poin 11 di atas), field JRXML-nya sudah menunggu kolom `catatan_khusus`, tapi query manual di `cetakPacs()` **tidak pernah ikut diupdate** untuk men-SELECT kolom itu — jadi begitu jasper coba baca field tsb dari ResultSet, kolomnya tidak ada. Diperbaiki dengan menambahkan `data_triase_pacs.catatan_khusus` ke SELECT list di `cetakPacs()`. Sudah dicek silang: semua field lain di JRXML (baris 106-167) sudah match dengan kolom di query manual ini, tidak ada yang hilang lagi. Build `ant jar` sukses.
